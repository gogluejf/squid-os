Style Label Consolidation — message.go + styles.go

Refactor all message renderers to use a unified StyleLabel-based approach. Pre-build every label type inline (like ToolStyle() / SkillStyle()), then pass the label directly to DrawCanvas.

Problem

Every renderer in message.go scatters its styles across many independent vars in styles.go:

RendererIndividual vars used
SystemSystemLabel, SystemParam, CanvasStatInline, TextMuted, BgApp
InternalInternalMsgLabel, InternalParam, CanvasStatInline, TextMuted, BgApp
SyntheticInternalLabel, InternalParam, CanvasStatInline, TextMuted, BgApp
ThinkingThinkingLabel, CanvasStatInline, TextMuted, BgApp
ToolToolLabel, ToolParamOnTool, ToolStatOnTool, ToolErrorOnTool, ToolResultOnTool, BgCode

That's a lot of standalone vars that should just be inline in a single struct. Tools already do it right with ToolStyle() and SkillStyle().

Plan

Step 1: Final StyleLabel struct

type StyleLabel struct {
    Label   lipgloss.Style  // label text (e.g. tool name, "thinking")
    Param   lipgloss.Style  // param/display value
    Dim     lipgloss.Style  // stats chips, separators, muted inline text
    Content lipgloss.Style  // body content when expanded
    Error   lipgloss.Style  // error text (fallback to Content if not set)
    Bg      string          // box background color name
    Fg      string          // default foreground color name
}

Dim is used for stats (tokens, duration) — not a separate Stat field.

Step 2: Inline pre-builders — replace all standalone vars

Build every StyleLabel inline, exactly like ToolStyle() does. No more standalone InternalMsgLabel, SystemLabel, CanvasStatInline, etc. All styles live inside the label:

Step 3: Refactor DrawCanvas to take StyleLabel

// Before
func DrawCanvas(parts []string, content []string, fg, bg string, topGap, width, marginBottom int) string

// After
func DrawCanvas(parts []string, content []string, s StyleLabel, topGap, width, marginBottom int) string

Inside DrawCanvas:

  • Box style uses s.Bg and s.Fg
  • Separator/arrow use s.Bg for background
  • Content section gets s.Content applied (wrap it)

Step 4: Update helpers

func drawCanvasSpan(parts, content []string, s StyleLabel, width int) string {
    return DrawCanvas(parts, content, s, 1, width, 0)
}

func drawToolBox(parts, content []string, s StyleLabel, boxWidth int) string {
    return DrawCanvas(parts, content, s, 2, boxWidth, 1)
}

func drawUserBox(parts, content []string, s StyleLabel, boxWidth int) string {
    return DrawCanvas(parts, content, s, 1, boxWidth, 1)
}

Step 5: Simplify renderers

// Before — scattered style refs
func renderThinking(...) string {
    parts := []string{
        style.ThinkingLabel.Render("thinking"),
        style.CanvasStatInline.Render(tokenChipOutput(...)),
    }
    ...
    return drawCanvasSpan(parts, content, style.P.TextMuted, width)
}

// After — single label
func renderThinking(...) string {
    s := style.ThinkingStyleLabel()
    parts := []string{
        s.Label.Render("thinking"),
        s.Dim.Render(tokenChipOutput(...)),
    }
    ...
    return drawCanvasSpan(parts, content, s, width)
}

Same pattern for all renderers. Stats use s.Dim, labels use s.Label, params use s.Param.

File Changes

styles.go

  • Expand StyleLabel: add Content, Error, Bg, Fg (keep Dim)
  • Add builder functions: SystemStyleLabel(), InternalStyleLabel(), SyntheticStyleLabel(), ThinkingStyleLabel()
  • Update ToolStyle(), SkillStyle() to fill new fields
  • Delete all standalone style vars that are now inlined

message.go

  • DrawCanvas: (fg, bg string) → (s StyleLabel), use s.Bg/s.Fg/s.Content
  • All helpers: take StyleLabel instead of fg string
  • All renderers: call style.XxxStyleLabel(), use s.Label, s.Dim, s.Param, s.Content
  • Streaming renderers: same treatment
